BEFORE WE START

The finding that reorders the priority list

Within its first hour, this research found a defect that changes the real state of the project. It comes first because no other priority makes sense until it is fixed.

The frontend has two API clients. One correct and one broken, and nobody uses the correct one.

// services/frontend/src/utils/api.js — the correct client
const API = import.meta.env.VITE_API_URL;        ← points to api.unistylescuracao.com
// Imported by: NOBODY. Zero files. It is dead code.

// What the site actually does, 23 times across 10 files:
await fetch('/api/auth/me', ...)          // contexts/AuthContext.jsx:26
await fetch('/api/orders', ...)            // pages/Checkout.jsx:111
await fetch('/api/payments/sentoo', ...)   // pages/Checkout.jsx:151
await fetch('/api/admin/stats', ...)       // pages/Admin.jsx:48
await fetch('/api/delivery/zones')        // hooks/useDeliveryZones.js:13

A relative path resolves against the domain that serves the page. In production that is unistylescuracao.com, which is nginx serving the frontend — not the API, which lives at api.unistylescuracao.com. And because it is an SPA, nginx answers any unknown path with index.html:

$ curl -s -o /dev/null -w "%{http_code} %{content_type}" \
    https://unistylescuracao.com/api/products
200 text/html     ← not a 404: it is the home page disguised as an API

Worse than a clean error. The code does if (response.ok), gets 200, enters the success branch and blows up when it tries response.json() on HTML. In AuthContext that lands in a catch that restores the session from localStorage without validating it, so the failure is silent.

Consequence, verified in production today: sign-up, login, session restore, the logged-in customer's cart, coupons, order creation, Sentoo payment, tracking, profile, admin panel and delivery zone calculation do not work on the live site. The catalogue does show, because it is the only thing requested directly from Directus. The shop looks fine but cannot sell.

This also explains an earlier symptom: the published bundle contained no reference at all to api.unistylescuracao.com. It was not just that the VITE_API_URL variable was missing at build time — the code does not read it in 23 of its 25 calls.

Fix

Replace the 23 calls with the client that already exists, or —faster and without touching 10 files— add a proxy from /api/ to the backend in the frontend's nginx. The second option has a real advantage: cookies and the token travel on the same origin, and CORS disappears. The first is cleaner to reason about. Pick one; the one that cannot stay is today's.

OptionWhat changesProsCons
A · nginx proxyOne location /api/ block in the frontend configA single change; same origin; no CORS; the code stays as isCouples frontend and API to the same domain
B · Use utils/api.js23 calls in 10 files + rebuild with VITE_API_URLClean separation; the client is already writtenLarger change surface; CORS must be configured
PART 1

Actors and what each one comes to do

A requirement without an actor is an opinion. These are the four that actually exist at Unistyles, with the job each comes to get done.

ActorWho they areWhat they come forWhere they live in the code
VisitorArrives from Instagram or WhatsApp, no accountSee whether her size is available and how much delivery to her neighbourhood costsPublic catalogue, cart in Redis, guest checkout
CustomerRegistered, repeat buyerBuy again without retyping her address; track her orderusers, addresses, carts, orders
OwnerPaulaPublish products, see orders, get paid, notify via WhatsAppDirectus + /api/admin/* + users.is_admin
External systemsSentoo, WhatsApp Cloud API, SMTPConfirm payments, deliver messages/api/payments/sentoo/webhook, /api/whatsapp/webhook

An actor the code invented that does not exist: pages/Admin.jsx checks user.role !== 'admin', but the users table has no role column — not in init.sql, not in init.v2.sql, not in any migration. It has is_admin BOOLEAN. On top of that, routes/auth.js:295 runs SELECT ... role ... FROM users, which on that database throws “column does not exist”. These are two different authorisation models in the same system, and neither of them works.

PART 2

Glossary: the language of the domain

One term, one meaning, the same in conversation, in the code and in the database. When this is skipped, you get bank versus bank_transfer and role versus is_admin.

TermMeans exactlyNot to be confused with
ProductThe catalogue entry: name, brand, description, photo. Lives in Directus. 285 today.Variant. A product is not sold: one of its variants is.
VariantThe specific size + colour combination, with its own stock and SKU. Only the 33 bras have them.Product. The variant is what actually leaves the stockroom.
SKUUnique code of a variant. Today BRA-001; it should encode brand, reference, size and colour.ref, which is the supplier's code (REF 011473) and repeats across variants.
ReferenceThe manufacturer's code, printed on the label.SKU. Leonisa sets the reference; you set the SKU.
CartA selection not yet paid for. In Redis for a guest, in carts when logged in.Order. A cart's price can change; an order's cannot.
OrderThe frozen document: prices, address and items exactly as they were at payment.Cart. An order is never recalculated.
ZoneOne of the three delivery areas in Curaçao, with its fee and its free-delivery threshold.Address. An address falls within a zone.
Order statusWhere the parcel is: pending, confirmed, shipped, delivered, cancelled.Payment status, which is a different column and a different state machine.

PART 6

User stories with acceptance criteria

Those for the critical epics, in a format that can be turned into an automated test without rewriting it. Each criterion is worded to be answered yes or no, never “more or less”.

US-01As a visitor I want to buy without creating an account, so I don't waste time on a form.BROKEN
Given I have items in the cart and I am not logged in
When I complete checkout with my name, phone and address
Then the order is created with a null user_id
And the order stores my phone and my email
And I receive an order number I can use to look it up later

Covers RF-E1 RN-01 · Blocked by the relative paths and the missing contact CHECK.

US-02As a customer I want to choose my size and see whether it is in stock, so I don't buy something that can't be shipped to me.BROKEN
Given a bra with size and colour variants
When I open its product page
Then I see only the combinations that exist
And the sold-out ones appear disabled, not hidden
And when I add it to the cart the variant is saved, not the size text

Covers RF-A5 RF-C4 RN-04 · Blocked by the 77 unloaded variants and the unnormalised size vocabulary.

US-03As a customer I want to know how much delivery to my neighbourhood costs before paying, so there are no surprises.BROKEN
Given I am at checkout
When I type my neighbourhood
Then the system infers my zone and shows the fee
And if my subtotal exceeds that zone's threshold, delivery drops to zero
And the total shown matches the amount charged

Covers RF-D1 RF-D2 RF-D3 RN-06 · Blocked by the relative path, unseeded neighbourhoods and three sources for the threshold.

US-04As a customer I want to pay by card and have the order confirmed only if the payment was really approved.BROKEN
Given an order awaiting payment
When I pay on the Sentoo gateway
Then the backend asks Sentoo for the status again before confirming
And if the same notification arrives twice, the order is not duplicated
And if the payment fails, the stock becomes available again

Covers RF-F1 RF-F4 RF-F5 RN-11 · The server logic is fine; the browser call fails and credentials are missing.

US-05As a customer I want to track my order by its number, so I know when it arrives without messaging on WhatsApp.BROKEN
Given I have an order number
When I enter it on the tracking page
Then I see the current status
And I see when it went through each previous status, with date and time
And I don't need to be logged in

Covers RF-G1 RF-G2 RN-12 · The page has existed for months and has no data to show: the history table is missing.

US-06As the owner I want to see my orders and change their status, so I can work without opening the database.BROKEN
Given I log in with my administrator account
When I go to /admin
Then I see sales, orders and customers
And I can move an order to “shipped”
And that change is recorded with its timestamp
And a regular customer who types /admin is sent back to the home page

Covers RF-H1 RF-H2 RF-H3 RN-14 · Blocked by two incompatible authorisation models: role versus is_admin.

US-07As the owner I want the welcome coupon to be used only once per customer, so I don't give away margin.BROKEN
Given a coupon flagged as “first order only”
When a customer who has already used it tries to apply it again
Then the system rejects it
And if her order is cancelled, the use is released and she can apply it again
And I can see how much discount each code gave away

Covers RF-E4 RN-07 RN-08 · Blocked by the absence of coupon_redemptions.

US-08As the owner I want to publish and withdraw products myself, without asking anyone for anything.DONE
Given I log in to the CMS
When I create, edit or withdraw a product
Then the change shows in the shop without rebuilding anything
And there is no need to touch SQL or any file in the repository

Covers RF-H4 RF-J1 RN-15 · It works. The only condition is never editing productData.js by hand again.

If only one thing could be fixed

The relative paths RF-K4. Not because it is the most serious design defect, but because it unblocks in one go twenty requirements that are already coded and today never get to run: sign-up, session, logged-in cart, coupons, order, payment, tracking, profile, admin panel and delivery zones. It is the change with the biggest gap between effort and effect in the whole project.

After that, in this order: the authorisation model RN-14, because without the panel the shop cannot be operated; the v2 schema with the variants loaded RN-04, because without it a size cannot be sold; and the missing credentials, which are not programming but paperwork — Sentoo, SMTP, WhatsApp and the real bank account number.
